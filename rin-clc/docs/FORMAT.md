# CLC Format Specification 1.0

**الحالة:** مستقر (Stable) — المُنفَّذ فعلياً في `src/clc_format.h` +
`src/clc_container.cpp` (هذا المستند يصف نفس التخطيط بالضبط، بلا انزياح عنه).

## 1. نظرة عامة

CLC (Rin Compact Library Container) صيغة حاوية ثنائية مستقلة بالكامل، بامتداد
`.rcl`. **ليست ZIP** ولا تحتوي أي بايت من بنية ZIP (`PK\x03\x04` وما شابه).
كل عدد صحيح في الصيغة **Little-Endian** بعرض ثابت، مُسلسَل يدوياً بايتاً
بايتاً (بلا الاعتماد على `sizeof(struct)`/padding أي مترجم أو منصة).

## 2. التخطيط الفيزيائي العام للملف

```
[Header: 96 bytes]  [Compressed Blocks (Data)]  [Metadata]  [Dependency Table]
[Rin Symbol Table]  [File Index]  [Block Table]  [Integrity: 32 bytes]  [Footer: 48 bytes]
```

الرأس دائماً عند offset 0. بقية الأقسام تُحدَّد بحقول offset صريحة في الرأس —
لا يعتمد المُحلِّل على ترتيبها الفيزيائي فعلياً (رغم أن الكاتب الرسمي يكتبها
بهذا الترتيب لتمكين streaming حقيقي: تُكتَب الكتل فور جاهزيتها بلا معرفة
حجم الفهرس مسبقاً).

## 3. الرأس (Header) — 96 بايت ثابتة

| Offset | حجم | الحقل | الوصف |
|---|---|---|---|
| 0  | 4 | `magic` | `"RCLF"` (0x52 0x43 0x4C 0x46) |
| 4  | 1 | `version_major` | `1` في CLC 1.0.0 |
| 5  | 1 | `version_minor` | `0` |
| 6  | 2 | `flags` (u16) | bit0=HAS_DEPENDENCIES، bit1=HAS_RIN_DICT، bit2=STREAMING_SAFE |
| 8  | 1 | `compression_method` | القيمة الافتراضية على مستوى الحاوية (0=STORE,1=DEFLATE,2=RIN_DICT_DEFLATE) |
| 9  | 1 | `level` | 0..4 أو 5=ultra |
| 10 | 2 | `reserved` | `0` |
| 12 | 4 | `file_count` (u32) | عدد سجلات File Index (يشمل المجلدات الفارغة) |
| 16 | 4 | `block_count` (u32) | عدد سجلات Block Table |
| 20 | 8 | `metadata_offset` (u64) | |
| 28 | 8 | `dependency_offset` (u64) | |
| 36 | 8 | `symbol_table_offset` (u64) | |
| 44 | 8 | `index_offset` (u64) | File Index |
| 52 | 8 | `block_table_offset` (u64) | |
| 60 | 8 | `data_offset` (u64) | يساوي دائماً 96 في هذا الإصدار |
| 68 | 8 | `integrity_offset` (u64) | |
| 76 | 8 | `footer_offset` (u64) | |
| 84 | 4 | `header_crc32` (u32) | CRC32 لبايتات 0..83 فقط (**لا يشمل نفسه ولا reserved2**) |
| 88 | 8 | `reserved2` | محجوز للتوسّع (CLC 1.1/2.0)، `0` حالياً |

**اكتشاف الإصدار قبل القراءة الكاملة**: يكفي قراءة أول 6 بايتات (`magic` +
`version_major` + `version_minor`) لمعرفة ما إذا كانت الأداة تدعم هذا الملف،
قبل تحليل أي حقل آخر.

## 4. Metadata

تسلسل: `str32(name)`, `str32(version)`, `str32(author)`, `str32(description)`,
`str32(license)`, `str32(rin_version)`, `str32(entry_point)`,
`str32(created)`, `str32(modified)`, `u32(extra_count)`, ثم لكل عنصر إضافي:
`str32(key)`, `str32(value)`.

`str32` = `u32(length) + UTF-8 bytes` بلا NUL نهائي — يدعم أي Unicode بما فيه
العربية بلا أي تحويل.

## 5. Dependency Table

`u32(count)` ثم لكل تبعية: `str32(name)`, `str32(constraint)` (مثال:
`"math"`, `">=1.2.0"`).

## 6. Rin Symbol Table

`u32(count)` (حتى 250) ثم لكل رمز: `str32(token)`. هذا هو القاموس المشترك
المستخدَم في مرحلة استبدال الرموز (§8).

## 7. File Index

`u32(count)` ثم لكل ملف/مجلد:

| الحقل | الحجم | الوصف |
|---|---|---|
| `path` | str32 | مسار نسبي بفواصل `/`، مُطبَّع، بلا `..` أو مسار مطلق |
| `original_size` | u64 | حجم المحتوى **الأصلي** (قبل أي تحويل) بالبايت |
| `flags` | u8 | bit0=IS_RIN_SOURCE، bit1=IS_TEXT، bit2=IS_DIR |
| `first_block` | u32 | فهرس أول كتلة في Block Table |
| `block_count` | u32 | عدد الكتل المتتالية المملوكة لهذا الملف |
| `content_hash` | 32 bytes | SHA-256 للمحتوى الأصلي الكامل (لِـ dedup والتحقق) |

مجلد فارغ: `flags` يحمل `IS_DIR`، و`block_count = 0`.

**Deduplication**: ملفان بنفس `content_hash` يُشيران لنفس مدى `(first_block,
block_count)` — لا تُخزَّن الكتل مرتين.

## 8. Block Table

`u32(count)` ثم لكل كتلة:

| الحقل | الحجم | الوصف |
|---|---|---|
| `id` | u32 | مُسلسَل بدءاً من 0 |
| `original_size` | u64 | حجم محتوى الكتلة *بعد* أي تحويل قاموس، *قبل* DEFLATE |
| `compressed_size` | u64 | حجم البايتات المخزَّنة فعلياً |
| `offset` | u64 | **نسبي** إلى `data_offset` (وليس مطلقاً من بداية الملف) |
| `method` | u8 | 0=STORE، 1=DEFLATE |
| `crc32` | u32 | CRC32 للبايتات المخزَّنة (سريع، لـ `clc check`) |

## 9. مرحلة استبدال قاموس Rin/النصوص (قبل DEFLATE)

لكل ملف بامتداد `.rin`/نصي (أو محتوى "يبدو نصياً" — بلا NUL bytes وأغلبه
مطبوع)، **قبل** التقسيم لكتل وقبل DEFLATE:

1. يُفحَص المحتوى بحثاً عن الرموز الموجودة في Rin Symbol Table (أطول تطابق
   أولاً عند كل موضع).
2. كل تطابق يُستبدَل بـ: بايت escape `0x01` + بايت مُعرِّف الرمز (0..249).
3. أي بايت `0x01` **حرفي** في المصدر الأصلي (نادر) يُهرَّب كـ `0x01 0xFF`
   (مُعرِّف محجوز `0xFF` يعني "أعِد 0x01 حرفياً").

هذا **عكوس بالكامل byte-for-byte** — عند فك الضغط تُجمَع كل كتل الملف أولاً
(inflate)، ثم تُطبَّق عملية الاستبدال العكسية **مرة واحدة على كامل الملف
المُجمَّع** (وليس لكل كتلة منفردة)، لأن تسلسل الـ escape (بايتان) قد يمتد عبر
حدود كتلتين متتاليتين.

## 10. Integrity Section — 32 بايت

SHA-256 محسوبة على **كل البايتات من `data_offset` وحتى نهاية Block Table**
(أي: الكتل + Metadata + Dependency Table + Rin Symbol Table + File Index +
Block Table مجتمعة). **لا يشمل الرأس نفسه** (لأن الرأس يُكتَب/يُعاد كتابته في
النهاية بعد معرفة كل الـ offsets، فلا يمكن أن يعتمد hash المحتوى عليه).

## 11. Footer — 48 بايت (نهاية الملف تماماً)

| Offset (من بداية Footer) | حجم | الحقل |
|---|---|---|
| 0 | 4 | `magic` = `"RCLE"` |
| 4 | 8 | `header_offset` (u64) — دائماً `0` في CLC 1.0 |
| 12 | 32 | نسخة من Integrity hash (نفس §10، للتحقق السريع من الذيل بلا تحليل كامل) |
| 44 | 4 | نسخة من `header_crc32` (للتحقق المتقاطع بلا حتى قراءة الرأس أولاً) |

قراءة آخر 48 بايت من الملف تكفي للتحقق من عدم truncation قبل أي تحليل آخر.

## 12. Compatibility / Versioning

- `version_major` مختلف عن الذي تدعمه الأداة → رفض فوري وواضح (رسالة خطأ
  صريحة تذكر الإصدارين).
- `version_minor` أعلى (نفس `major`): الأداة **يجب** أن تحاول القراءة عادةً
  (حقول 1.1 الجديدة، إن وُجدت مستقبلاً، ستُضاف في `reserved2` أو كحقول
  إضافية داخل `extra` في Metadata — لا تُغيَّر الحقول الحالية أبداً).
- `reserved`/`reserved2` يجب أن تبقى `0` في الكاتب الرسمي لـ 1.0، وتُتجاهَل
  بأمان من أي قارئ لا يعرفها.

## 13. لماذا هذا التصميم وليس غيره؟ (قرارات موثَّقة)

- **الضغط "غير صلب" (كل ملف/كتلة مستقلة)** بدل ضغط كل شيء كتدفّق واحد: يسمح
  بـ (أ) استخراج ملف واحد (`clc extract`) بلا فك المشروع كاملاً، (ب) تدفّق
  حقيقي بذاكرة محدودة عند pack/unpack. **الكلفة**: نسبة ضغط أقل قليلاً من
  أدوات solid archive على مشاريع كثيرة الملفات النصية الصغيرة — مُقاس
  وموثَّق بصدق في `benchmarks/results.md`، وليس مُخفى.
- **قاموس مشترك على مستوى الحزمة كاملة** (وليس لكل ملف): يلتقط التكرار عبر
  الملفات (نفس الكلمات المفتاحية تتكرر عبر ملفات Rin مختلفة)، بكلفة ذاكرة
  صغيرة (≤250 نصاً قصيراً).

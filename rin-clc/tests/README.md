# الاختبارات

الاختبار الحقيقي (pack → unpack → مقارنة byte-for-byte + أمان + تلف) مبني
**داخل** الأداة نفسها ويُشغَّل عبر:

```bash
./build/clc test
```

هذا مُتعمَّد (وليس نقصاً): يضمن أن أي بناء لـ `clc` — على أي جهاز، بلا أي
إطار اختبار خارجي (GoogleTest/Catch2 إلخ) — يحمل حزمة تحقّق ذاتي كاملة معه.
المصدر: [`../src/cli/self_test.cpp`](../src/cli/self_test.cpp).

الحالات المُغطاة فعلياً (14 اختباراً، كلها ناجحة في هذا التسليم):

1. مشروع فارغ
2. ملف واحد
3. ملفات كثيرة (200 ملف)
4. ملف ثنائي كبير (6 MB، يفرض المسار المُتدفِّق streaming)
5. محتوى Unicode/عربي
6. ملف ثنائي (غير نصي)
7. ملفات متطابقة (يتحقق أن dedup يُشير فعلياً لنفس الكتل، لا نسخ متعددة)
8. مجلدات متداخلة + مجلد فرعي فارغ
9. مشروع Rin واقعي (ملفات مختلطة)
10. مستوى `--ultra`
11. رأس تالف (يُرفَض بنظافة)
12. Path Traversal (`..`) — مرفوض
13. مسار مطلق — مرفوض
14. اكتشاف تلف بيانات (قلب بايت واحد، `clc check` يكتشفه بالضبط)

## `enable_testing()` عبر CMake

إن استُخدِم `CMakeLists.txt` (بدل `build.sh` المباشر)، فـ `ctest` يشغّل نفس
الأمر عبر `add_test(NAME clc_self_test COMMAND clc test)`.

# جسر Rin ⇄ indsin: الأقواس `<< >>`

القاعدة: **Rin للبيانات والمنطق، وindsin يرسم الواجهة.** كل ما بين `<<` و`>>` هو كود Rin؛ المترجم
(`rin_indsin_tags.h`) يحوّله نصّاً قبل التحليل، فيعمل في كل المضيفين (أندرويد، سطح المكتب، CLI، المعاينة الحيّة)
دون تعديل المحلّلات. المصدر بلا `<<` يخرج حرفاً بحرف، وعدد الأسطر محفوظ (أرقام الأخطاء صحيحة).
`a << b` داخل كود Rin العادي أو `<Rin>`/`<Fun>` لا تتأثّر.

## 1) ربط بيانات Rin — `<<expr>>`
تعبير Rin نقي (متغيّرات، دوال، فهرسة، `user.name`، مقارنات…) يُعاد حسابه تلقائياً عند تغيّر أي `warp` يدخل فيه.
يعمل في ثلاثة مواضع:

| الموضع | المثال |
|---|---|
| داخل نص ابن | `<Text>Hi <<user.name>>!</Text>` |
| قيمة سمة | `<Button label=<<title>> />` · `visible=<<n > 3>>` |
| داخل سلسلة بين علامتي اقتباس | `<Text text="Count = <<count>>" />` |
| وحدها في موضع عنصر | `<<user.name>>` ⇒ عنصر `Text` جاهز |

## 2) طباعة ناتج — `<<print …>>` و`<<run f(args)>>`
* `<<print a, b>>` يعرض القيم مفصولة بمسافة كما تفعل `print` (`<<print "n:", count + 1>>` ⇒ `n: 4`). تفاعلية.
* `<<run report(n)>>` **يستدعي دالة `fun` من Rin ويعرض ما طبعته** (فإن لم تطبع شيئاً عُرضت قيمتها المُعادة):

```rin
<Rin> fun report(n) { print "items: " + n; print "sum: " + (n * 10); } </Rin>
<Card><Text><<run report(count)>></Text></Card>
```
`<<run>>` تُترجَم إلى `indsin.run("report", count)`: **مُخزَّنة بمفتاح (الاسم + الوسائط)** فلا تُنفَّذ إلا مرة لكل
وسائط مختلفة، وتُعاد فقط حين يتغيّر وسيط `warp`. لإجبار إعادة التنفيذ مرّر خلية عدّاد كوسيط. خطأ الدالة يظهر
في الواجهة كنص `⚠ …` بدل أن يُسقطها. الاسم معرّف عادي (`fun` عامة أو دالة أصلية).

دوال Rin الجديدة (تُستعمل في أي برنامج، لا في indsin فقط):

| الدالة | تعيد |
|---|---|
| `captureOutput(fn, ...args)` | نصّاً: كل ما طبعته `fn` (تقبل قيمة دالة أو اسمها) — لا يتسرّب إلى ناتج البرنامج |
| `capture(fn, ...args)` | `map {ok, output, result, error}` — لا ترمي أبداً |
| `indsin.run(name, ...args)` | نص للعرض، مُخزَّنة (هي الوحيدة المسموحة داخل خصائص الواجهة؛ `captureOutput`/`capture` ممنوعتان هناك بحارس النقاء) |

## 3) عبارات (على سطر مستقل)
| الصيغة | المعنى |
|---|---|
| `<<let x = expr>>` | `let x = expr;` — داخل عنصر تُرفع إلى آخر الملف (الواجهة تُقيَّم بعد التشغيل) |
| `<<warp n = 0>>` | خلية حالة تفاعلية |
| `<<import "lib/ui">>` | `@import "lib/ui";` |
| `<<if c>> … <<else if c2>> … <<else>> … <</if>>` | شروط تفاعلية (تُترجَم إلى `visible=`، مثل `<If>`) |
| `<<each list as it, i>> … <</each>>` | تكرار على بيانات Rin |

## 4) التكرار على بيانات Rin — `<<each>>`
```rin
<Rin> let people = [{"name":"Ali","age":30}, {"name":"Sara","age":25}]; </Rin>
<<each people as p, i>>
  <Card#row><Text#nm><<i + 1>>. <<p["name"]>> (<<p.age>>)</Text>
            <Button onTap={select(i)}>Pick</Button></Card>
<</each>>
```
* `list` مصفوفة Rin (متغيّر أو استدعاء)، أو رقم (`<<each 5 as k>>`)، أو مصفوفة حرفية (`["a","b"]`).
* `it` تصير `(list)[k]` و`i` تصير `k`؛ أسماء `#id` تأخذ لاحقة `_0 _1 …` (`nm_0`، `row_1`).
* **مرّر الفهرس `i` للمعالجات** (`onTap={select(i)}`)؛ تمرير `p` نفسه يصل المعالج كنص.
* الحجم يُقاس بتشغيل تجريبي للبرنامج على مفسّر مؤقّت ثم يُوسَّع المصدر (انظر `expandTagSyntax` في
  `rin_indsin_pipeline.h`)؛ بلا `each` غير حرفية لا كلفة إضافية. ما يظهر من أثر جانبي في الجزء التجريبي (ملف/شبكة) يحدث مرتين.
* الحجم يُقاس عند التحميل: أي تعديل لمصدر فيه `each` في الجلسة الحيّة يمرّ بإعادة تحميل كاملة (مفسّر جديد).
* غير مدعوم (برسالة واضحة بسطرها): `each` متداخلة (انقل الحلقة الداخلية إلى `<Define>`)، وقائمة نصّية/قاموس.

## الأخطاء
`unterminated '<<' (missing '>>')` · `<<if>> opened at line N is not closed` · `<<else>> without a matching <<if>>` ·
`<<let …>> is a statement` (داخل نص/سمة) · `nested <<each>>` · `<<each …>>: expected an array or a number`.

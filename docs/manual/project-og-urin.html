project.og.urin — البيانات الوصفية لمشروع Rin#

ملف في جذر كل مشروع يديره التطبيق. هو حاوية Rin مصغّرة (@container=ProjectMeta … .end/container) من أسطر key="value";. يحمل هوية المشروع (النوع، المعرّف، الإصدار، المؤلف…) ويُنقل داخل حزم RinPak كأي ملف (content/project.og.urin).
الإصدار الحالي schema=2 (الإصدار 1 كان type فقط)
الترميز UTF-8، الحد الأقصى 64KB
الكاتب/القارئ RinProjectMeta.kt (أندرويد) • urin_parse/urin_render في tools/rinpak.py (مرجع، نفس القواعد)

الشكل#

# بيانات وصفية لمشروع Rin — يُدار تلقائياً من التطبيق، يمكن تعديله بحذر
// الحقول: النوع، المعرّف، الإصدار، المؤلف، الرخصة، الوسوم، الصلاحيات...
@container=ProjectMeta
    schema=2;
    type="ui";
    id="my-shop";
    name="MyShop";
    version="1.2.0";
    description="متجر تجريبي";
    author="ana";
    license="MIT";
    tags="demo,shop";
    created="2026-10-11T12:00:00Z";
    modified="2026-10-11T15:30:00Z";
    minRinVersion="1.0.0";
    permissions="network";
    dependencies="math,@rin/strings";
    icon="assets/icon.png";
.end/container

الحقول#

الحقل الوصف الحد
schema إصدار الصيغة (رقم بلا علامات اقتباس) —
type container \| table \| ui \| free \| illust \| html \| html_js (غير ذلك ⇒ free) [A-Za-z0-9_]
id معرّف مستقر [a-z0-9._-] يبقى عند إعادة التسمية والإصدارات (يُشتق من الاسم؛ للأسماء العربية من SHA-256) 64
name اسم العرض = اسم مجلد المشروع (يُحدَّث عند إعادة التسمية) 64
version / minRinVersion إصدار المشروع / أدنى إصدار Rin يلزمه 32
description، author، license وصف حر، المؤلف، الرخصة 1000 / 128 / 64
tags، permissions، dependencies قوائم مفصولة بفواصل 16×32 / 64×64 / 64×128
created، modified ISO-8601 (modified يتحدّث مع كل تعديل من التطبيق) —
icon مسار نسبي لصورة PNG ≤ 512KB داخل المشروع تصبح أيقونة الحزمة المصدَّرة 256
أي مفتاح آخر يُحفظ في extra ويُعاد كما هو (≤32 مفتاحاً، القيمة ≤512) — لا تضيع حقول إصدارات أحدث —

القيم النصية تُهرَّب: \\ \" \n \r \t. القوائم تُقصّ وتُنظَّف (فراغات/عناصر فارغة).

التوافق#

  • الصيغة الخام القديمة (type=container سطراً بسطر) وصيغة الحاوية v1 تُقرآن بلا ترحيل يدوي؛ وأول كتابة من التطبيق ترقّي الملف إلى v2.
  • التطبيقات القديمة تلتقط أول type=… في الملف: يُكتب type أولاً دائماً، ولا يُستعمل أي اسم حقل ينتهي بـ type، وتعليقات الرأس لا تحوي type=.
  • سطر غير مفهوم يُتجاهل؛ ملف تالف أو أكبر من 64KB ⇒ يُعامَل كغير موجود (free).

العلاقة بـ RinPak#

  • التصدير: ProjectManager.exportProject يقرأ الملف ويملأ المانيفست (id, version, description, author, license, tags, permissions, dependencies, minRinVersion) ويختار الأيقونة (icon إن كانت PNG صالحة، وإلا شعار RinPak المضمّن res/raw/rinpak_pack_icon.png).
  • الاستيراد: المانيفست المتحقَّق منه يتقدّم على أي قيم مناقضة في الملف المضمَّن (لأن المانيفست هو ما رآه المستخدم في المعاينة ويغطيه التوقيع)؛ بقية الحقول (icon, extra, created) تبقى. إن غاب الملف (حزمة من أداة خارجية) يُنشأ من المانيفست. الاسم يصبح اسم المجلد النهائي (قد يُرقَّم MyApp_2) وid يبقى.
  • التحرير: «⋮ ← تفاصيل المشروع» في شاشة المشاريع، أو python3 tools/rinpak.py meta <dir> --set version=1.1.0.

أمان#

  • الملف بيانات فقط: لا يُنفَّذ ولا يمنح أي صلاحية. permissions وصف يُعرض في المعاينة ويُحلَّل (SENSITIVE_PERMISSIONS).
  • مسار icon يمرّ بنفس فحص المسارات الآمنة (بلا .. ولا مقاطع مخفية) ويُرفض إن كان خارج المشروع أو ليس PNG أو أكبر من 512KB.

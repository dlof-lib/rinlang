block-frames.md — بداية الكتل ونهايتها (Block Frames)#

كل ما في هذه الصفحة جُرِّب على المحلِّل الحقيقي (rin_parser.cpp). الاختبارات: tests/verification/block_braces.rin وtests/diagnostics/block_frames/.

الفكرة#

كل كتلة بيانات في Rin (@container · @Volume · @Containers.Group · @element · @loop · @view · @theme · @make · Section · Translations · .object("id")) لها إطار (Frame) واحد يحدّد بدايتها ونهايتها. للإطار شكلان فقط، ويُحسم الشكل عند الفتح ولا يتغيّر:

الشكل الفتح الإغلاق الإغلاق المسمّى (اختياري)
أقواس على طريقة C++ (الموصى به) @kind[.sub][=name] { على نفس السطر }; (وتُقبل } وحدها) }=name;
وسم (القديم، ما زال يعمل) @kind[.sub][=name] .end/kind أو .end; .end/kind=name 
@Volume=shop {
    @container=cart {
        state total = 0;
        fun add(n) { total = total + n; return total; }

        @element.button=buy {
            text = "Buy";
        };

        on.buy.click = add(5);
    };
};                                  // مثل: class Shop { ... };  في C++

الصياغة النحوية (EBNF)#

block        = header , ( brace_body | tag_body ) ;
header       = "@" , kind , [ "=" , name ] ;          (* أو .object("id") *)
brace_body   = "{" , { statement } , "}" , [ "=" , name ] , [ ";" ] ;   (* "{" على نفس سطر الترويسة؛ ";" على نفس سطر "}" *)
tag_body     = { statement } , ".end" , ( ";" | "/" , kind , [ "=" , name ] ) ;

قواعد منع التعارض#

  1. { تفتح الكتلة فقط إن كانت على نفس سطر الترويسة. { على سطر جديد تبقى عبارة عادية (كتلة محلية) داخل الشكل القديم، فلا يتغيّر معنى أي كود كُتب قبل هذه الميزة.
  2. لا خلط داخل كتلة واحدة. كتلة فُتحت بـ { لا يغلقها .end/…، والعكس صحيح — يُرفض بخطأ E0011 يذكر سطر الفتح والإغلاق الصحيح.
  3. التعشيش حرّ بين الشكلين: كتلة أقواس داخل كتلة وسوم وبالعكس، لأن لكل كتلة إطارها المستقل (مكدّس RAII في المحلِّل، يُسحب حتى عند الخطأ فلا يبقى إطار يتيم بعد الاسترداد).
  4. { } الخاصة بالدوال والشروط والحلقات لا علاقة لها بالإطار — لها محلِّل كتل منفصل، فلا يمكن لـ } نهاية دالة أن تُغلق كتلة @container بالخطأ.
  5. ذيل ; على طريقة C++: }; هو الإغلاق القياسي (كما في class/struct/enum)، و; اختيارية وتُستهلك فقط إن وقعت على نفس سطر }.
  6. الاسم في الإغلاق اختياري ومُتحقَّق منه: }=name; يجب أن يطابق @kind=name، ويُرفض إن كانت الكتلة بلا اسم. مفيد في الملفات الكبيرة المتعشّشة (يلعب دور } // namespace X، لكن يُفحص فعلاً).
  7. نهاية الملف تغلق الملف فقط، لا الكتل. ملف ينتهي وكتلة مفتوحة يُرفض برسالة تذكر سطر الفتح.

جدول البنى#

البنية أين تُغلق
كل @… أعلاه و.object("id") إطار كتلة (أقواس أو وسم)
fun · if · when/otherwise · while · for · match · class · enum · on init() {…} · goal {…} } فقط — كتل لغة عادية
[ … ] · {"k": v} · ( … ) حرفيات وتعابير، ليست كتلاً
عبارة بسيطة ;

رسائل الخطأ#

الحالة الرمز المثال
فُتحت بـ { وأُغلقت بـ .end E0011 @container opened with { at line 1 must be closed with }
فُتحت بلا { وأُغلقت بـ } E0011 … without { must be closed with .end/container (or .end;)
اسم الإغلاق لا يطابق E0011 closing }=b does not match the opening name a
انتهى الملف والكتلة مفتوحة E0012 @Volume opened with { at line 1 was never closed

الترحيل#

لا حاجة له: الشكل القديم يعمل كما هو. لتحويل كتلة: ضع { في نهاية سطر الترويسة، وبدّل .end/kind بـ };. النتائج متطابقة سلوكياً (جرى التحقق بمقارنة مخرجات 59 اختبار تحقّق قبل/بعد).

حدود هذا الإصدار#

  • مفسِّر rin (المحرّك الكامل) يدعم الشكلين. أمّا rinc (المترجم الأصلي لمجموعة فرعية) فمحلِّله منفصل (rinc.cpp) ويقبل الوسوم فقط حتى الآن.
  • تلوين المحرّرات (syntaxes/, editors/, VS) لم يُحدَّث ليميّز }=name.
  • رسالة التتبّع وقت التشغيل ما زالت تطبع ✅ .end/container (name) بصرف النظر عن شكل الإغلاق (حفاظاً على ملفات .expected القائمة).

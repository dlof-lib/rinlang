لماذا؟ (الفجوة التي تسدّها)#

كان في Rin التقاط للأخطاء (try/catch/throw) لكن بلا أي ضمان للتنظيف: ملف فُتح، اتصال، حاوية، قفل، أو حالة مؤقتة — كلها تبقى معلَّقة إذا خرج الكود مبكراً بـreturn أو break أو خطأ. وكان كل catch يلتقط كل شيء بلا فلترة، فلا يمكن معالجة خطأ معيّن وترك البقية تصعد.

هذه الإضافة تجمع أربع كلمات سياقية (غير محجوزة، فلا تكسر أي اسم متغيّر قديم) تشكّل معاً عقداً واحداً:

ما تفتحه تغلقه، وما تلتقطه تحدّده، وما لا تعرفه يكمل طريقه كما هو.

الصيغة المعنى
try { } finally { } finally يُنفَّذ دائماً عند مغادرة try (طبيعي، return، break، continue، خطأ)
try { } catch (e) { } finally { } الثلاثة معاً
defer <عبارة>; تأجيل عبارة إلى لحظة مغادرة الكتلة الحاوية (LIFO: آخر ما أُجِّل أول ما يُنفَّذ)
catch (e) when (شرط) { } بند catch بحارس؛ يمكن كتابة عدّة بنود، وأول مطابق يفوز
rethrow; يعيد رمي الخطأ الذي يعالجه أقرب catch كما هو (يحفظ code/message/line)

finally#

try {
    print "work";
} finally {
    print "always";
}
  • يعمل مع return داخل الدالة: يُنفَّذ قبل الخروج وتبقى قيمة return.
  • لو لم يوجد catch فالخطأ يكمل صعوده بعد finally (لا يُبتلع).
  • لو أنهى finally نفسه بـreturn/break/continue فهو يحسم النتيجة ويلغي الخطأ المعلَّق. (استخدمه عمداً فقط.)

defer#

fun report(path) {
    defer print "closing", path;      // يُنفَّذ آخراً
    defer print "flushing";           // يُنفَّذ أولاً
    print "writing";
    return true;
}
  • defer يلفّ ما بعده في نفس الكتلة داخل try { … } finally { عبارة } وقت التحليل، فالنتيجة نفس ضمانات finally بالضبط (أي مسار خروج، ترتيب LIFO).
  • العبارة المؤجَّلة تُقيَّم عند الخروج لا عند السطر (مثل finally)، فترى آخر قيم المتغيّرات.
  • كتلة كاملة مسموحة: defer { a(); b(); }.
  • داخل حلقة: يعمل في كل دورة عند نهاية جسم الحلقة (حتى مع continue/break).
  • على مستوى الملف: يعمل عند نهاية البرنامج. ⚠️ ما بعده يصبح داخل نطاق فرعي، فضعه في أول الملف أو داخل دالة.
  • defer بعد = أو ( أو . أو [ تبقى اسماً عادياً: let defer = 5; صالح.

catch … when#

try {
    openAccount(id);
}
catch (e) when (e.code == "E_NOT_FOUND") { print "no such account"; }
catch (e) when (e.code == "E_DENIED")    { print "permission denied"; }
catch (e)                                { print "unexpected:", e.message; }
  • الحارس يُقيَّم بعد ربط المتغيّر e.
  • لو لم يطابق أي بند، يكمل الخطأ الأصلي صعوده إلى المُعالج الأبعد (أو finally ثم الأعلى).
  • catch when بلا متغيّر خطأ غير مسموح (الحارس يحتاج e).

توحيد شكل الخطأ: e.code للجميع#

  • أخطاء النظام: e.code = E0021… (كما كان).
  • throw لقاموس فيه code: يظهر e.code مباشرة (وتبقى القيمة الأصلية في e.value).
throw {"code": "E_NOT_FOUND", "message": "missing"};
// في catch:  e.code == "E_NOT_FOUND"   و   e.value.message == "missing"

rethrow#

try {
    try { let x = [1, 2][10]; }
    catch (e) { print "logging", e.code; rethrow; }   // يرمي E0021 الأصلي نفسه
} catch (outer) { print outer.code; }                 // E0021

مسموح داخل catch فقط (خطأ تحليل واضح خارجه).

كيف تتماسك مع بقية Rin#

  • الحاويات والمكتبات: أي مورد (file، http، قاعدة بيانات الحاويات) يُغلَق بـdefer/finally مهما كان مسار الخروج.
  • retry: يعمل كما كان؛ ويمكن وضع defer داخل جسمه (ينفَّذ في كل محاولة).
  • #ignorance وtry { } catch { } القديمة: بلا أي تغيير في السلوك.
  • المفسِّر والـVM: العبارات الجديدة تُنفَّذ عبر المفسِّر مباشرة (تفويض من الـVM)، فالنتيجة واحدة بلا ازدواج منطق.

حدود معروفة (صراحةً)#

  • لا defer بقيَم مُلتقَطة وقت السطر (نمط Go)؛ التقييم عند الخروج.
  • rin build (rinc) يدعم المجموعة الفرعية فقط؛ العبارات الجديدة تعمل عبر rin run.
  • مفسّر Go (gorin) لم يُحدَّث بعد.

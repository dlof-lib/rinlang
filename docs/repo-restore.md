# استرداد المستودعات (GitHub وغيره) في RinStudio

يسترد مستودعاً كاملاً (أو مجلداً منه) إلى مشروع جديد، أو داخل مجلد في مشروع موجود، ويتذكّر مصدره ليُحدَّث لاحقاً.

## المصادر المدعومة
| المصدر | أمثلة مقبولة |
|---|---|
| GitHub | `https://github.com/o/r`، `o/r`، `github:o/r`، `git@github.com:o/r.git`، `.../tree/dev/src`، `.../releases/tag/v1` |
| GitLab (gitlab.com وأي مضيف يبدأ بـ `gitlab.`) | `https://gitlab.com/group/sub/proj/-/tree/main/docs` |
| Bitbucket | `https://bitbucket.org/o/r/src/main/app` |
| Codeberg / Gitea / Forgejo | `https://codeberg.org/o/r/src/branch/dev` |
| أي رابط ZIP مباشر (https) | `https://example.com/pack.zip` |

حقل «فرع / وسم / commit» يتقدّم على ما في الرابط. زر «اختيار» يسرد أول 100 فرع ووسم (ما عدا روابط ZIP المباشرة).
اسم فرع يحوي `/` اكتبه في حقل الفرع مباشرة (الرابط يلتقط المقطع الأول فقط).

## أين تجدها
- **المشاريع ← استيراد ← من مستودع**: ينشئ مشروعاً جديداً (النوع يُستنتج: `main.rin` ← حر، `index.html` ← HTML/HTML+JS).
- **الملفات ← رفع ← استرداد من مستودع**، و**أدوات المشروع ← استرداد من مستودع / تحديث من المصدر المحفوظ**.
- الرابط في الحافظة يُقترح تلقائياً عند فتح الحوار.

## طرق الدمج (داخل مشروع موجود)
1. **إضافة الجديد فقط**: لا يلمس أي ملف موجود.
2. **استبدال المختلف (الافتراضي)**: يضيف الجديد ويستبدل المختلف؛ الأصل يُنسخ أولاً إلى `.rin_backup/restore_<تاريخ>/`.
3. **مطابقة تامة**: كالسابق، وما ليس في المستودع يُنقل إلى النسخة الاحتياطية (مع تأكيد قبل التنفيذ).

الملفات المحمية لا تُلمس أبداً: `.rin_*` و`project.og.urin` (في جذر المشروع). الملف المطابق في المحتوى يُعدّ «دون تغيير».

## المصدر المحفوظ
بعد كل استرداد يُكتب `.rin_repo.json` في المجلد الوجهة (المزوّد، المضيف، المسار، الفرع، المجلد الفرعي، طريقة الدمج، وقت الجلب).
**لا يُحفظ أي رمز سرّي.** «تحديث من المصدر المحفوظ» يقرؤه من المجلد الحالي أو أقرب مجلد أب، ويسمح بتغيير الفرع قبل التنفيذ.

## الأمان والحدود
- https فقط، والتحويلات تُتبع يدوياً (حتى 5).
- الرمز (اختياري، للمستودعات الخاصة) لا يُحفظ، ويُرسل لمضيف الطلب الأول فقط؛ يُسقَط عند التحويل لمضيف تخزين آخر.
- فكّ ZIP آمن ضد Zip Slip؛ مجلدات `.git` تُتجاهل؛ حدود: 20000 ملف، 256 ميغابايت إجمالاً، 100 ميغابايت للملف.
- المشروع الجديد يُبنى في مجلد مؤقت مخفي ثم يُنقل ذرّياً؛ الإلغاء أو الفشل لا يترك مشروعاً ناقصاً.
- GitHub بدون رمز يستعمل رابط الأرشيف العام (لا يستهلك حدّ طلبات API)؛ مع الرمز يستعمل API.

## غير مدعوم حالياً (بصراحة)
- أرشيفات tar.gz، وGists، وGitHub Enterprise، ومضيفات GitLab/Gitea ذات أسماء لا تبدأ بـ `gitlab.`/`gitea.` أو لا تحوي `forgejo` (استعمل رابط ZIP المباشر لها).
- لا يُجلب سجلّ git (التاريخ)؛ الاسترداد لقطة من الملفات.
- لم يُجرَّب البناء/الاختبار على جهاز أو Gradle في بيئة التطوير هذه (انظر ملف CHANGELOG).

## الملفات
جديد: `RepoCore.kt` (منطق خالص قابل للاختبار)، `RepoRestore.kt` (الواجهة والشبكة)، `strings_repo.xml` ×4، `fx_repo.xml`، `RepoCoreTest.kt`.
معدّل: `ProjectManager.kt` (دالتان: `newImportTempDir`، `installImportedTree`)، `FilesActivity.kt` (3 عناصر قائمة)، `ProjectsActivity.kt` (قائمة اختيار الاستيراد).

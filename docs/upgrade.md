# Background of the computational upgrade — خلفية الترقية الحسابية

> كل مثال هنا جُرِّب فعلياً عبر المفسِّر (انظر `tests/print/upgrade_*.rin`). المكتبة: `lib/upgrade.og.rin`.
> إضافة بحتة: لا كلمات جديدة في اللغة، ولا يتأثر أي كود موجود.

## الفكرة في جملة
**حاوية تُرقّي حسابها بنفسها في الخلفية**: القارئ يأخذ جوابه فوراً من النسخة الحيّة، وفي الظلّ تُجرَّب نسخة أحدث (أسرع، أدقّ، مصحَّحة) على **نفس الدخلات الحقيقية**؛ فإذا أثبتت نفسها **تُرقّى ذرّياً** مع هجرة الحالة، وإن انكشفت بعد الترقية **تتراجع وحدها**. وبالمثل: الجواب الواحد يبدأ تقريبياً وفورياً ثم **يرتقي دقّةً** في الخلفية.

## المشكلات التي يعالجها
| المشكلة المعروفة في اللغات | الوضع المعتاد | هنا |
|---|---|---|
| تحديث منطق برنامج يعمل بلا إيقافه | إعادة تشغيل، أو Hot-swap هشّ (Erlang) بلا ضمان للحالة | ترقية بين قراءتين، ذرّية مع الحالة |
| تحسين/إعادة كتابة دالة دون يقين بالتكافؤ | اختبارات تغطّي ما خطر على المبرمج فقط | **ظلّ على الدخلات الحقيقية** حتى `need` أدلّة، رفض عند أول اختلاف |
| الجواب الدقيق بطيء والسريع خاطئ | اختر أحدهما | الاثنان: خشن فوراً، ثم يرتقي في الخلفية (Anytime) |
| هجرة المخطّط/الحالة نصف المكتملة | بيانات تالفة عند منتصف الفشل | الهجرة داخل معاملة واحدة مع الترقية؛ فشلها يتراجع بكل شيء |
| اكتشاف الانحدار بعد النشر | مراقبة خارجية وتراجع يدوي | فترة مراقبة `soak`: القديمة تبقى ظلّاً عكسياً وتراجع تلقائي |
| فشل عمل الخلفية يُسقط البرنامج أو يختفي | استثناء في خيط منسيّ | الفشل يُعزل ويُسجَّل؛ القارئ لا يراه أبداً |
| اختبار ما يجري في الخلفية غير حتمي | `sleep` وسباقات | يجري كله على ساعة Rin المجمَّدة ⇒ مخرجات حتمية |

## المفاهيم الناضجة المدموجة
| المفهوم | من أين | دوره هنا |
|---|---|---|
| Shadow / Canary | نشر البرمجيات | تجربة المرشّحة على الدخل الحقيقي دون أثر |
| Hot code swap | Erlang/OTP | الاستبدال دون إيقاف |
| المعاملات والتراجع | `container.transaction` · `trial` | ذرّية الترقية والهجرة والتراجع |
| هجرة المخطّط | Rails/Alembic | `migrate` / `unmigrate` تتراجعان مع المعاملة |
| الحوسبة المتدرّجة | Anytime algorithms | `refine`: مستويات دقّة |
| المؤقّتات والساعة المجمَّدة | `timers.*` · `time.freeze` | الخلفية حتمية |
| نوع الحاوية المفحوص | `defineContainerType` | حالة الخلية نفسها حاوية: كل كتابة تُفحَص (مرحلة خاطئة ⇒ E0004) |
| الإقرار البشري | `dialog` · `Intent.guard` | `approve` يصلح أن يستدعي حواراً |

## الاستعمال
```kotlin
@import "lib/upgrade.og.rin";
time.freeze();
Upgrade.cell("sum", fun(n) { let s = 0; for (let i = 1; i <= n; i = i + 1) { s = s + i; } return s; });
Upgrade.proposeWith("sum", fun(n) { return n * (n + 1) / 2; }, {need: 3, soak: 5s});
let r = Upgrade.read("sum", 40);     // {value, version, stage}
Upgrade.run(10ms);                   // تُجري الخلفية شريحتها (في برنامج حقيقي: تجري مع المؤقّتات)
```

## الواجهة
| الدالة | المعنى |
|---|---|
| `Upgrade.cell(name, fn)` · `cellWith(name, fn, opts)` | خلية بنسخة 1. `opts`: `need` (أدلّة، افتراضي 3) · `tol` أو `eq(a,b,input)` أو `score(value,input)` + `slack` |
| `Upgrade.read(name, input)` | يخدم من النسخة الحيّة ويجدول عمل الظلّ في الخلفية. يعيد `{value, version, stage}` |
| `Upgrade.propose(name, fn)` · `proposeWith(name, fn, opts)` | يرشّح نسخة جديدة (واحدة في كل مرة) |
| `Upgrade.refine(name, tiers)` · `refineWith(name, tiers, opts)` | تحسين تدريجي: `tiers` من الأسرع إلى الأدقّ؛ `opts`: `step` (افتراضي 100ms) · `onUpgrade(info)` |
| `Upgrade.get(name, input)` | جواب فوري من أعلى مستوى جاهز: `{value, tier, of, final}` |
| `Upgrade.state(name)` · `Upgrade.timeline(name)` | الحالة · سجلّ مقروء بكل ما جرى |
| `Upgrade.run(مدّة)` | تقدّم الجدولة (= `timers.run`) |

**خيارات `proposeWith`**: `need` · `maxBad` (اختلافات مسموحة، افتراضي 0) · `soak` (مدّة مراقبة بعد الترقية) · `touch: [حاويات]` (تدخل في المعاملة) · `migrate()` / `unmigrate()` · `approve(info)` ⇒ `true` للموافقة · ومعايير الحكم `tol`/`eq`/`score`.

## آلة الحالات (حقل `stage` في حاوية `up_<name>`)
```
steady ──propose──▶ shadowing ──need أدلّة + approve──▶ [معاملة: migrate + استبدال] ──▶ soaking ──انتهت المدّة──▶ steady
                        │ اختلاف/خطأ                       │ فشل الهجرة                    │ اختلاف عكسي
                        ▼                                   ▼                              ▼
                      رفض (steady)                     رفض + تراجع كل شيء          تراجع تلقائي (steady، rollbacks+1)
```
وضعان للحكم: **مكافئ** (الافتراضي: النتيجة نفسها ضمن `tol`، للتحسين الأدائي وإعادة الكتابة) و**أفضل** (`score`: لا تسوء الجودة، لتغيير الخوارزمية).

## الضمانات
- **القارئ لا يدفع إلا ثمن النسخة الحيّة**، ولا يصله خطأ المرشّحة أبداً (`upgrade_reject`).
- **الاستبدال ذرّي**: الحالة + الهجرة + `live` في معاملة واحدة؛ فشل أي جزء يعيد كل شيء ويبقى `v1` يخدم (`upgrade_migrate_fail`).
- **تراجع ذرّي** يعكس الهجرة بـ `unmigrate` (`upgrade_rollback`).
- **الحتمية**: كل ما في الخلفية على `timers`؛ مع `time.freeze()` المخرجات متطابقة دائماً.
- **التحسين التدريجي رتيب**: لا ينزل المستوى، وفشل مستوى يترك الجواب الأقدم سليماً (`upgrade_refine`).

## حدود صريحة
- «الخلفية» = شرائح مجدوِل تعاونية (`timers`) لا خيوط متوازية؛ تُنفَّذ بعد تسليم الجواب للقارئ، لا أثناءه.
- دوال النسخ **يجب ألا تكون ذات أثر جانبي** (تُنفَّذ مرتين: حيّة وظلّ).
- الأدلّة إحصائية (`need` عيّنات حقيقية) وليست برهاناً على التكافؤ؛ ارفع `need` وطوّل `soak` لما هو حرج.
- التراجع يشمل حقول الحاويات المذكورة في `touch` فقط (قاعدة `trial`/المعاملة نفسها: لا يتراجع `print` ولا الملفات).
- ترقية واحدة جارية لكل خلية؛ `propose` أثناءها خطأ E0007.
- النسخ دوال في الذاكرة ولا تُحفَظ على القرص (ترقية عابرة للتشغيل تحتاج تكاملاً مع `rinpak`، لم يُنفَّذ).

## اتجاه مستقبلي (غير منفَّذ — اقتراح صيغة)
إن أردت الفكرة كلمة سياقية على نسق `val`/`timer`، فهذا الشكل يُترجَم مباشرة إلى المكتبة أعلاه:
```kotlin
@shop.container
    let price = 10;
    val total = price * qty;
    upgrade total { v2 = price * qty * (1 + tax)  need 3  soak 1m  migrate { ... } }
.end;
```

## الأخطاء
`E0007` خلية غير معروفة/موجودة · ترقية جارية · مستويات أقل من 2 — `E0004` (من `UpgradeCell`) قيمة حقل غير مسموحة.
